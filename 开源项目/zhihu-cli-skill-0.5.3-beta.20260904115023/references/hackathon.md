## 参赛流程

### 1. 完成报名

在活动页面进入报名流程，填写个人、联系方式和学校等信息，并按页面要求完成身份验证。

报名成功后，按页面提示添加活动小助手并加入官方交流社群，以获取赛程通知、赛事答疑和组队信息。

### 2. 创建或加入队伍

登录活动页面，进入“我的项目”：

- 单人参赛可以直接创建自己的队伍；
- 团队参赛由队长创建队伍并邀请队员；
- 被邀请的队员需要先完成报名；
- 队员通过知乎昵称搜索和邀请；
- 按页面要求填写队伍名称、成员、合影和参赛想法链接等信息。

队伍信息发生变化时，应在活动允许的时间内及时更新。

### 3. 开发作品

确定作品目标和使用的知乎能力后，完成可在线访问的产品 Demo。

黑客松项目可以使用知乎开放平台提供的搜索、热榜、直答、关注与用户数据等能力。具体可用命令、接口、认证方式和返回字段，以本 Skill 的对应 Reference 和 CLI `capabilities`、`--help` 输出为准。

黑客松另外提供知乎故事与知识内容接口。需要使用时读取 [黑客松故事与知识内容 API](hackathon-content-api.md)。

调用有额度限制的开放能力时，应在应用层进行缓存和请求去重。禁止批量、高频、无意义发布，或使用接口进行刷屏、恶意灌水和垃圾内容推送。

### 4. 创建黑客松项目

作品提交入口开放后，由队长在活动页面进入队伍详情，点击“创建项目”。

按页面要求填写：

- 项目名称；
- 参赛主题或赛道；
- 项目介绍；
- 可运行的线上 Demo 地址；
- 产品说明或计划书；
- 项目 icon 和封面图；
- GitHub/Gitee 仓库地址（选填）；
- 演示视频地址（选填）；
- 知乎登录回调地址（使用 OAuth 时填写）。

项目保存后仍可在活动允许的范围内继续修改；最终应在截止时间前完成发布。

## 知乎账号 OAuth

黑客松项目可以接入知乎 OAuth，实现：

- 使用知乎账号登录第三方应用；
- 获取登录用户的昵称、头像等基础公开信息；
- 在用户授权后读取其创作、关注和收藏等公开范围数据。

创建黑客松项目后，活动页面会为项目分配 OAuth `app_id` 和 `app_key`。两者代表第三方应用，不能作为知乎 CLI 使用的 Access Secret。项目是否实际接入 OAuth，由开发者决定。

| 凭证 | 用途 |
|---|---|
| OAuth `app_id` | 标识黑客松项目，可用于构造授权地址 |
| OAuth `app_key` | 应用后端换取 OAuth access token，必须保密 |
| OAuth access token | 标识当前完成授权的知乎用户 |
| Access Secret | 鉴权开放平台调用方，与 OAuth App Key 不同 |

使用 OAuth 时：

1. 在活动页面填写回调地址。
2. 应用中的 `redirect_uri` 必须与活动页面登记值完全一致。
3. App Key、OAuth Token 和 Access Secret 只能保存在后端或安全凭证系统中，不得进入前端、URL、日志、截图或代码仓库。
4. 知乎最终授权确认必须由用户本人完成。

具体授权地址、回调参数、换取 Token 的请求方式和安全边界，读取 [黑客松 OAuth 接入](hackathon-oauth.md)。

代表 OAuth 授权用户调用创作、关注和收藏等接口时，同时读取 [用户数据 API](user-api.md)。

CLI 的普通使用模式只通过 Access Secret 读取该凭证所属账号的数据，不发起 OAuth，也不接受用户 OAuth Token。两种鉴权流程应分别处理。

## 提交作品

作品提交时间为 2026 年 9 月 13 日 10:00 至 9 月 15 日 10:00。由队长进入活动页面完成提交。

### 必交材料

- 可公开访问并能实际操作的线上 Demo；
- 产品说明或计划书。

产品说明是初审的重要材料，应说明：

- 项目的核心创作思路和目标用户；
- 用户如何完成核心体验；
- 整体技术方案；
- 使用了哪些知乎开放能力；
- 项目与知乎社区生态的契合点；
- 项目对社区用户的实际价值。

### 选交加分材料

- GitHub 或 Gitee 代码仓库；
- 在线演示视频。

### 提交前检查

1. Demo 可以从公网正常打开并完成核心流程。
2. 项目名称、介绍、赛道、封面和产品说明已经完成。
3. 代码仓库和视频链接可以被评委访问。
4. 使用 OAuth 时，回调地址与活动页面登记值完全一致。
5. App Key、Access Secret、OAuth Token 等凭证没有出现在代码仓库、前端响应、日志、截图或视频中。
6. 接口失败、额度耗尽和空数据都有真实的错误或降级提示。
7. 页面显示、接口调用和登录流程经过实际运行验证，避免将“代码已完成”描述为“线上已可用”。
