## 1. 设计语言

一句话：**暖调手绘纸感**。

| 维度 | 取值 | 说明 |
|---|---|---|
| 底色 | 米白纸感 `#f8f0df` + 纸纹叠加 | 全站统一，不用纯白 |
| 主色 | **暖珊瑚 `#e2664f`** | 主按钮、选中态、进度条、数据面 |
| 文字 | 深褐墨色 `#381508` | 不用纯黑，保留纸墨感 |
| 描边 | 深褐 `rgba(83,42,23,.52)`，1.6~1.8px | 圆头圆角，模拟手绘线 |
| 圆角 | **非对称**手绘圆角 | 见 §2.2 `--r-hand` |
| 字体 | 标题书卷气衬线体；UI 控件用楷体 | 见 §3.3 |
| 禁止 | 冷调科技蓝、条纹/网格纹理、硬边色块、重投影 | 历史踩坑见 §7 |

### 1.1 为什么主色是暖珊瑚而不是蓝色

蓝色在此前的版本中是主色（`#0d64fd`）。改为暖珊瑚后，**蓝色只保留给知乎品牌入口**——
这样"知乎授权"这件事在视觉上是唯一的蓝，反而更醒目。

## 2. 设计 Token（唯一事实来源）

原型通过 `zhiyu-theme.css` 的 `:root:root` 覆盖页面自带的旧 token
（旧值为冷调科技蓝，`--accent: #0d64fd` 等 7 个 hex）。迁移到 Next.js 时
**应直接把下表写进 `globals.css` 的 `:root`**。

### 2.1 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#f8f0df` | 页面底色 |
| `--surface` | `#fff9eb` | 卡片 / 面板底 |
| `--fg` | `#381508` | 主文字、墨线 |
| `--muted` | `#8a6047` | 次要文字 |
| `--border` | `rgba(83,42,23,.22)` | 常规边框 |
| `--accent` | `#e2664f` | 主色 |
| `--accent-deep` | `#c9503a` | 主色按压态 / 强调文字 |
| `--accent-tint` | `#ffb4a0` | 进度条渐变亮端 |
| `--zhihu-blue` | `#0084ff` | **仅**知乎授权入口 |
| `--line` | `rgba(83,42,23,.52)` | 手绘描边 |
| `--line-soft` | `rgba(83,42,23,.24)` | 浅描边、分隔线 |
| `--danger` | `#d8503f` | 危险操作 |

派生色（**必须在 `:root` 就地求值，不能只改 `--fg`/`--accent`，
否则不会跟着变**——这是实际踩过的坑）：

| Token | 定义 |
|---|---|
| `--fg-soft` | `color-mix(in oklch, var(--fg) 7%, transparent)` |
| `--fg-softer` | `color-mix(in oklch, var(--fg) 4%, transparent)` |
| `--accent-soft` | `color-mix(in oklch, var(--accent) 15%, transparent)` |
| `--accent-faint` | `color-mix(in oklch, var(--accent) 6%, transparent)` |

投影：

| Token | 值 |
|---|---|
| `--shadow` | `0 8px 22px rgba(95,55,24,.10), 0 2px 4px rgba(78,38,18,.08)` |
| `--shadow-lg` | `0 18px 48px rgba(95,55,24,.18), 0 4px 10px rgba(78,38,18,.10)` |

### 2.2 形状与字体

| Token | 值 | 说明 |
|---|---|---|
| `--r-hand` | `15px 11px 16px 12px` | 手绘非对称圆角（上左/上右/下右/下左） |
| `--r-hand-lg` | `22px 17px 24px 19px` | 大卡片 |
| `--r-hand-pill` | `999px` | 胶囊 |
| `--font-hand` | `"Kaiti SC", STKaiti, KaiTi, "Noto Serif SC", "Source Han Serif SC", serif` | 手写体，**只用于 UI 控件** |
| 标题字体 | 沿用页面自带的 `--font-display`（宋体族） | **不要**把手写体重定向给 `h1/h2` |

> **为什么标题不用手写体**：`--font-display` 被 `h1/h2/品牌字/引文` 共用，
> 一旦重定向为手写体，整页会失去阅读秩序。手写体只给品牌字与控件（按钮/页签/导航/标签/提示）。

### 2.3 纸纹

```css
body {
  background-color: var(--bg);
  background-image: url("./assets/textures/paper.png");
  background-size: 620px 620px;
  background-attachment: fixed;
}
body::after {                    /* 细颗粒噪点，模拟纸张印刷质感 */
  content: ""; position: fixed; inset: 0; z-index: 9; pointer-events: none;
  opacity: .14; mix-blend-mode: multiply;
  background-image: radial-gradient(rgba(70,39,20,.32) .45px, transparent .6px);
  background-size: 4px 4px;
}
```

## 6. 相遇雷达（发现页）

### 6.1 定位

发现页的**第二种结果视图**，与卡片列表并存，通过「卡片 / 相遇雷达」切换器切换。
三种结果来源（找特定的人 / 随机推荐 / 快速匹配）都支持切换，**共用同一份筛选结果**。

解决的问题：卡片列表一次只能看几个，无法表达"谁离我更近"。
雷达以「我」为中心，一次呈现全部候选的关系分布。

### 6.2 视觉构成

| 元素 | 说明 |
|---|---|
| 中心 | 用户头像（`assets/characters/self.webp`）88px + 外圈彩色弧 + 「我」标签 |
| 轨道环 | 虚线同心圆，环上标注该处对应的相似度「≈ 78%」 |
| 连线 | 从中心到每个人，虚线，珊瑚→金黄渐变 |
| 人物节点 | 头像 84px 圆形描边 + 右侧标签卡（名字 / 人格倾向 / 相似度） |
| 装饰点 | 彩色小圆点，纯装饰，确定性随机（固定种子） |
| 相似度最高者 | 头像边框转主色 + 右下角 ✓ 徽标 |

### 6.3 布局算法：排序螺旋

```
半径 = RADIUS_MIN + SPACING × √rank        // rank 按相似度降序
角度 = rank × 黄金角(137.5°)
```

| 参数 | 值 |
|---|---|
| `RADIUS_MIN` | 170 |
| `SPACING` | 235 |
| 角度步进 | 黄金角 ≈ 137.5° |

**为什么用螺旋而不是"半径线性映射分数 + 碰撞推挤"**：
后者在 16 人时实测仍有 **7 组重叠**。根因是想同时满足「半径严格映射分数」
与「零重叠」，在给定画幅下**不可兼得**（分数集中在 69~88 区间时所有人被塞进同一圈，
推挤只能改角度不能改半径）。

改为排序螺旋后：半径随名次**单调递增**（「越近越同频」严格成立），
黄金角保证**任意两人不重叠**（实测 0 组）。代价是半径不再精确等于分数值，
但视觉上读起来一样。

### 6.4 交互

| 操作 | 行为 |
|---|---|
| 拖拽 | 平移画布（位移超过 **5px** 才认定为拖拽，否则视为点击） |
| 滚轮 | 以**光标位置为锚点**缩放 |
| `+` / `−` | 以视口中心为锚点缩放 |
| **全览** | 整幅缩进视口，一次看到全部人（默认取景） |
| **聚焦我** | 放大到以「我」为中心，标签清晰可读 |
| **点击头像** | **打开对方的人格卡** |
| 缩放范围 | `0.3 ~ 2.4`，初始取景为「全览」 |

### 6.5 两个必须遵守的实现约束

**① 只在确认拖拽后才 `setPointerCapture`**

指针一旦被捕获，后续 `pointerup` / `click` 的 `target` 会被**重定向到捕获元素**，
于是「点头像」永远命中不到头像。必须等位移超过阈值、真正开始拖拽时再捕获。

**② 命中判定要带坐标兜底**

拖拽路径下 `click.target` 仍会是视口容器。所以判定顺序是：
`e.target.closest('[data-action="profile"]')` → 失败则
`document.elementFromPoint(e.clientX, e.clientY).closest(...)`。

## 7. 头像生成规则

用户的知乎头像抓不到时，用本地角色插画兜底。

| 规则 | 规定 |
|---|---|
| 来源 | `assets/characters/`，7 张池（`linyue` `chenyu` `suqing` `limeng` `zhaoyi` `zhouming` `newfriend`） |
| 中心头像 | 固定 `self.webp` |
| 映射 | **按人物 id 确定性哈希**：`h = (h×31 + charCode) % 100000`，取模池长度 |
| 优先级 | `persona.avatarUrl`（真实知乎头像）> 本地兜底 |

> **为什么必须确定性**：否则同一人在雷达与人格卡弹窗里会显示两张不同的脸。
> 这是实际踩过的坑。

## 8. 已知取舍与历史坑（避免重犯）

| # | 坑 | 结论 |
|---|---|---|
| 1 | 重定向 `--font-display` 给手写体 | 标题全变手写体，失去阅读秩序。手写体只给控件 |
| 2 | `--fg-soft` 等派生色未在覆盖层重新求值 | 只改 `--fg` 不会让它们跟着变 |
| 3 | 给 `padding: 0` 的列表盒只加边框 | 文字贴边压线。加边框必须同时给内边距 |
| 4 | 在弹窗内的容器贴纯色底 | 弹窗是"纸 + 纸纹"，贴纯色会在 padding 区露出硬边色带，内容区反而参差，看起来像"容器到一半、文字在外面"。**容器的底色应让所在面板贯通** |
| 5 | 用 `Range.getClientRects()` 量"墨迹出盒" | 返回的是**行盒**，行高越大越"出盒"，不是视觉墨迹。**修复让指标变差时，先怀疑指标** |
| 6 | `pointerdown` 无条件 `setPointerCapture` | 见 §6.5① |
| 7 | 用 JS `el.click()` 测指针交互 | 合成事件不经过 pointer 序列，**测不出指针捕获类缺陷**。必须用真实鼠标/触摸事件 |
| 8 | XML 注释里写 `-----` | XML 规范禁止注释含连续两个短横线，SVG 会解析失败显示破图 |
| 9 | 小字号配大 letter-spacing | 会把标签撑宽、显得超出容器。标签类文字字距控制在 `0.02em` 内 |
