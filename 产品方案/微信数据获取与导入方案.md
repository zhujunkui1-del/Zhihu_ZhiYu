# 微信数据获取与导入方案（决策记录）

> 状态：已确认方向，尚未开发。本文是“知遇 ZhiYu”产品微信数据接入的架构决策记录，需求细节若有更新以此文件为准。

> 关联文档：本文属于《多平台数据接入方案.md》的“微信”专项；微信的取数决策不变，其余来源（QQ / 飞书 / 钉钉 / 知乎 / SBTI）见多平台方案。

## 1. 背景与约束

- 微信没有面向个人聊天记录读取的官方开放接口；聊天数据加密存储在本机微信客户端，解密 key 存在于本机运行中的微信进程内存。
- 网页/浏览器沙箱无法读取本地微信数据库或获取进程 key，服务器端（含 Vercel）也没有用户微信进程与数据，因此**微信聊天记录获取只能发生在用户本机**。
- 知遇线上平台唯一部署平台为 Vercel（见根目录 AGENTS.md）；本地数据能力必须与线上平台分离。

## 2. 决策：双形态分工

### 2.1 Web 版（Next.js / Vercel）

Web 版**不内嵌任何微信本地获取能力**，只提供两种能力：

1. **聊天记录 JSON 上传**：用户在页面上传导出的聊天 JSON 文件。
2. **获取指引**：引导用户使用可导出微信聊天数据的本地工具（如 WeFlow、WeChatMsg/PyWxDump 等）导出 JSON，再回到网页上传。

上传后的处理链路：

```text
用户上传 JSON
        ↓
服务端短期保留（必要时清洗/转码）
        ↓
Speaker 清洗（区分 self / other）
        ↓
Persona 蒸馏（对接 Distilly 一类蒸馏能力）
        ↓
结构化 Persona 入库（PostgreSQL）
        ↓
原始 JSON 删除，不留长期存储
```

### 2.2 桌面软件版（知遇本地客户端）

桌面版把 WeFlow 的微信数据能力**整体移植进知遇自身**，用户无需单独安装 WeFlow，只需安装知遇桌面客户端 + 同一台电脑上登录微信桌面版 4.0+。

桌面版提供两种 JSON 获取交互，两种方式共用同一条本地清洗/蒸馏管线：

| 模式 | 交互 | 说明 |
|---|---|---|
| 手动提供 JSON | 用户选择/拖入已导出的聊天 JSON 文件 | 与 Web 上传同构，文件不离开本机即可完成蒸馏 |
| 自动获取 JSON | 应用自动检测本机微信数据目录 → 获取解密 key → 解密并导出 JSON | 用户只需“打开微信并登录”，交互最顺滑 |

自动获取的链路：

```text
本机微信桌面版 4.0+（用户已登录）
        ↓
定位微信数据目录与本人账号
        ↓
获取解密 key（进程级，受微信版本与系统策略影响）
        ↓
解密读取会话与消息
        ↓
导出统一 JSON（含 sender / accountName / timestamp / type / content）
        ↓
Speaker 清洗 → Persona 蒸馏
        ↓
仅上传结构化 Persona 到知遇线上平台；原始 JSON 留本地或由用户决定删除
```

## 3. 边界与合规

- 只处理**用户本人、本机、经授权**的聊天数据；对外表述用“导出/读取本机数据”，不使用“破解/获取他人数据”等措辞。
- 原始聊天记录不作为线上长期存储对象：Web 上传版“用后即删”，桌面版默认“本地处理、只上传 Persona”。
- 本地获取能力只存在于桌面客户端，永不部署到 Vercel；Vercel 只承载 Web / API / Workflows / PostgreSQL。
- WeFlow 采用 CC BY-NC-SA 4.0 许可：若桌面版直接移植其代码，该部分将受“非商业 + 相同方式共享”约束；正式集成前需评估改用 clean-room 自研或合规授权路径。

## 4. MVP 优先级建议

- P0/P1（Web）：知乎 OAuth + SBTI + 微信 JSON 上传（含工具指引），先跑通“Persona → 匹配 → Agent → 报告”闭环。
- P1+（桌面）：微信自动获取作为演示加分项，需要现场一台微信 4.x 电脑。
